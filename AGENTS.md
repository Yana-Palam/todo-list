# Інструкції для AI-агентів

## Перед змінами
- Прочитай README.md, DOCUMENTATION_STRUCTURE.md та цей файл.
- Перевір фактичні конфігурації й наявні зміни. Не перезаписуй сторонню роботу.
- Якщо вимоги неоднозначні, запропонуй прості варіанти до реалізації. Не додавай архітектуру чи бібліотеки без потреби.

## Стек
React, TypeScript (strict), Vite, LESS, Axios; зовнішній Mock REST API — MockAPI.io (https://mockapi.io/); перевірка коду — ESLint.
Середовище: Node.js 24+ та npm. Версії залежностей зафіксовані у package-lock.json.

## Організація коду
- src/components — спільні компоненти; src/pages — компоненти сторінок.
- src/api — Axios-клієнт та CRUD-функції ресурсу todos.
- src/types — спільні типи; src/hooks — повторно використовувані React-хуки.
- src/styles — глобальні LESS-стилі. Стилі окремого компонента можна розміщувати поруч із ним.
- Компоненти називай у PascalCase, хуки — useSomething. Уникай передчасних абстракцій.
- Застосунок реалізує CRUD, фільтри та стани завантаження/помилок. Не додавай демонстраційні завдання під час запуску.
- src/hooks/useTodos.ts відповідає за серверний стан; src/pages/TodoPage.ts — за композицію сторінки та фільтр; компоненти форми й рядка — у src/components.

## TypeScript та LESS
- Зберігай strict, не використовуй any для обходу типізації. Невідомі зовнішні дані описуй як unknown і звужуй тип.
- Використовуй import type для імпорту типів; типізуй параметри та відповіді API.
- Використовуй .less, змінні та помірну вкладеність. Не додавай іншу систему стилізації без обґрунтування.
- Vite компілює імпортовані LESS-файли завдяки devDependency less; окремий плагін не потрібен.

## API
- Використовуй apiClient із src/api/client.ts; не дублюй Axios-інстанси та базову URL.
- VITE_API_BASE_URL задається через середовище. Фактичну базову URL MockAPI.io надає користувач; не вигадуй URL, шлях ресурсу чи fallback.
- .env.example містить надану користувачем базову URL MockAPI.io без шаблону :endpoint. Узгоджений ресурс — todos; шлях /todos задано константою TODOS_ENDPOINT у src/api/todos.ts. Застосунок запускається без API; apiClient відхиляє запит, якщо базову URL не задано.
- Не зберігай секрети у VITE_*: вони потрапляють до браузера.
- API-функції розміщуй у src/api, обробляй помилки явно; не приховуй їх порожніми catch.
- src/api/todos.ts реалізує GET, POST, PUT, DELETE через apiClient. PUT замість PATCH погоджено користувачем: CORS MockAPI.io не дозволяє PATCH із браузера. Не додавай проксі без потреби.
- Todo у src/types/todo.ts: id і title — string, completed — boolean, createdAt — ISO-рядок дати. Перевіряй зовнішні відповіді під час виконання; не маскуй некоректні дані порожнім списком.
- Не зберігай завдання в localStorage. Оновлюй стан після підтвердження API, зберігай введений текст при помилці, блокуй дубльовані зміни під час запиту.
- GET скасовується при демонтажі або повторному завантаженні. Не допускай застосування застарілих відповідей.
- Не додавай локальний сервер API, файл бази даних або тестові записи.

## Команди та перевірки
- npm ci — відтворюване встановлення.
- npm run dev — Vite; MockAPI.io працює як зовнішній сервіс і не потребує локального npm-скрипту.
- npm run lint — ESLint без попереджень; npm run typecheck — TypeScript.
- npm run build — перевірка TypeScript та production build у dist.
- npm run check — ESLint і production build; npm run preview — перегляд dist.
- Після змін запускай відповідні перевірки; перед завершенням конфігураційних змін — npm run check.
- Оновлюй документацію разом із командами, структурою, змінними середовища та залежностями.
