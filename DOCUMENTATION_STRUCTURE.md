# Структура документації

Документація пояснює, як запустити проєкт і підтримувати його без припущень про майбутню функціональність.

## Файли в корені
- README.md — початок роботи, директорії, середовище, команди та поточні межі проєкту.
- AGENTS.md — обов'язкові правила для AI-агентів: стек, код, стилі, API та перевірки.
- DOCUMENTATION_STRUCTURE.md — призначення документації та правила її підтримки.
- .env.example — публічний приклад конфігурації середовища без секретів; VITE_API_BASE_URL містить надану користувачем базову адресу MockAPI.io без шаблону :endpoint.
- package.json — фактичні команди та діапазони версій; package-lock.json — точні версії встановлення.

## Оновлення
1. Перед змінами прочитай README.md, AGENTS.md та цей документ.
2. Оновлюй документацію у тому самому наборі змін, що змінює поведінку, структуру, команди або конфігурацію.
3. Пиши українською, стисло; описуй реалізований стан. Плани чітко позначай як плани.
4. Звіряй команди з package.json, змінні — з .env.example і кодом, структуру — з файлами.
5. Не копіюй точні версії всіх залежностей у документацію: джерелом є package-lock.json.
6. Не додавай секретів, локальних шляхів користувача та неперевірених результатів перевірок.
7. Нові документи додавай лише за реальною потребою; пояснюй їхнє призначення тут і додавай посилання з README.md.

Окрема директорія документації на початковому етапі не потрібна.

## Документування API
- Бекенд Todo List — зовнішній сервіс [MockAPI.io](https://mockapi.io/); HTTP-клієнт — Axios.
- README.md описує налаштування VITE_API_BASE_URL у .env.local, схему Todo, CRUD і перевірки; AGENTS.md — правила використання src/api/client.ts, src/api/todos.ts та керування станом.
- Не вигадуй адресу API, шлях ресурсу чи модель завдання. Їх потрібно документувати після отримання фактичних даних від користувача.
- Базову адресу та ресурс todos узгоджено з користувачем: README.md описує повну адресу, src/api/todos.ts містить TODOS_ENDPOINT зі значенням /todos. Модель Todo визначено в src/types/todo.ts.
- CRUD реалізовано через GET, POST, PUT та DELETE. Використання PUT замість PATCH погоджено через обмеження CORS MockAPI.io; це рішення потрібно зберігати в документації.
- Локальна база, localStorage та локальний API-сервер не використовуються.
- Перевірку зовнішнього API документуй лише після отримання адреси й фактичного виконання запитів.
