# Мета та план Todo List

План складено після першої реалізації. Він описує межі поточного MVP,
а не відновлює історію початкового планування.

## Мета та користувач

Користувач веде власний список справ: створює завдання, змінює назву й статус,
видаляє їх і знаходить активні або виконані справи. Дані зберігаються у MockAPI.io.

## MVP

CRUD, три фільтри, лічильник активних, адаптивний інтерфейс українською,
завантаження, порожній стан, помилки та повторне завантаження.
Авторизація, категорії, дедлайни, локальне зберігання й власний бекенд поза MVP.

## Етапи та критерії готовності

1. Конфігурація та API: тип Todo, CRUD, перевірка відповідей. Некоректні дані й
   відсутня URL дають явну помилку; оновлення використовує погоджений PUT.
2. Серверний стан: зміни після підтвердження API, блокування повторних операцій,
   скасування GET та ігнорування застарілих відповідей.
3. Інтерфейс: форма, рядок, фільтри, стани сторінки. Введений текст зберігається
   при помилці; доступні клавіатурне керування й мобільний вигляд.
4. Контроль якості: збережені тести API та useTodos, ручна перевірка UI.
   npm run check проходить; тести не звертаються до зовнішнього API.
5. Документація: команди відповідають package.json, план і журнал доступні з README.

Перші три етапи реалізовано в початковому коміті. Повторювані тести та уточнення
документації додано наступним кроком.
