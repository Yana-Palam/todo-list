# Todo List

Адаптивний застосунок українською: React + TypeScript + Vite, LESS, Axios та MockAPI.io.

## Можливості

- Завантаження, створення, редагування назви, зміна статусу та видалення завдань.
- Фільтри «Усі», «Активні», «Виконані» та кількість активних завдань.
- Стани завантаження, порожнього списку, помилки та повторного завантаження.
- Зміни відображаються після підтвердження API. При помилці текст форми зберігається.
- Порожні назви після trim не приймаються; максимум 200 символів.
- Редактор підтримує Enter для збереження та Escape для скасування.
- Під час запиту зміни заблоковано, щоб уникнути повторних операцій.
- Завдання зберігаються лише у MockAPI.io; localStorage не використовується.

## Запуск

Потрібні Node.js 24+ і npm.

~~~sh
npm ci
~~~

Якщо .env.local ще немає, скопіюй приклад:

~~~powershell
Copy-Item .env.example .env.local
~~~

У .env.local:

~~~dotenv
VITE_API_BASE_URL=https://6aba693d5b549d818d6262f1.mockapi.io
~~~

~~~sh
npm run dev
~~~

Адреса Vite за замовчуванням — http://localhost:5173; фактична адреса відображається в терміналі.
Після зміни env перезапусти Vite; для production потрібна нова збірка.
Змінні VITE_* публічні: не зберігай у них секрети.

## MockAPI.io

У проєкті MockAPI.io має існувати ресурс todos.
Базова URL не містить /todos або шаблону :endpoint.
Повний endpoint: https://6aba693d5b549d818d6262f1.mockapi.io/todos.

| Поле | Формат |
| --- | --- |
| id | Рядок, генерується MockAPI.io |
| title | Рядок |
| completed | Boolean |
| createdAt | Рядок дати ISO 8601 |

Під час створення клієнт надсилає title, completed: false і поточний createdAt.
Отримані записи перевіряються під час виконання. Некоректні дані спричиняють видиму помилку.
Нові завдання додаються на початок поточного списку; після перезавантаження зберігається порядок відповіді API.

| Операція | Запит |
| --- | --- |
| Список | GET /todos |
| Створення | POST /todos |
| Назва або статус | PUT /todos/:id |
| Видалення | DELETE /todos/:id |

**PUT замість PATCH погоджено користувачем.** Під час перевірки MockAPI.io повернув
Access-Control-Allow-Methods: GET,PUT,POST,DELETE,OPTIONS. PATCH проходить із серверного клієнта,
але блокується CORS у браузері. Застосунок працює напряму, без проксі.

Усі запити використовують apiClient та VITE_API_BASE_URL. За відсутності URL запити
відхиляються до відправлення, а сторінка показує помилку й кнопку повтору.
Якщо отримано 404, перевір ресурс todos і базову URL у панелі MockAPI.io.
Після мережевої помилки запис міг бути збережений сервером: онови список перед повторним створенням.

## Структура

~~~text
src/
  api/client.ts          Axios, baseURL і timeout 10 секунд
  api/todos.ts           CRUD, перевірка відповідей і тексти помилок
  components/TodoForm.tsx
  components/TodoItem.tsx
  hooks/useTodos.ts      серверний стан, завантаження, зміни, помилки
  pages/TodoPage.tsx     сторінка, фільтри та лічильники
  types/todo.ts          Todo, TodoUpdate, TodoFilter
  styles/global.less    адаптивні стилі, LESS-змінні
  App.tsx               кореневий компонент
  main.tsx              вхід React
  vite-env.d.ts          тип змінної середовища
~~~

LESS компілюється Vite без додаткового плагіна. TypeScript працює у strict-режимі.
Для тестів додано Vitest, Testing Library та jsdom як залежності розробки.

## Автоматичні тести

Запусти npm run test. src/api/todos.test.ts перевіряє формат відповідей, CRUD-контракт, кодування id та відсутню URL. src/hooks/useTodos.test.ts перевіряє завантаження, повтор після помилки, підтвердження змін, блокування повторних операцій та скасування GET із захистом від застарілих відповідей.

Тести підставляють відповіді локально: MockAPI.io та .env.local не потрібні. UI і CORS перевіряються вручну.

## Ручна перевірка

1. Завантаж список; перевір порожній стан і кількість активних.
2. Додай завдання; переконайся, що пробіли без тексту не надсилаються.
3. Відредагуй назву; перевір збереження та скасування.
4. Зміни статус; перевір усі три фільтри та лічильник.
5. Перезавантаж сторінку; перевір збереження на сервері.
6. Видали створене для перевірки завдання.
7. При недоступному API перевір помилку та повторне завантаження.
8. Перевір мобільну ширину та керування з клавіатури.

## Результати початкової перевірки реалізації

- npm run check: ESLint, TypeScript та production build пройшли.
- У браузері перевірено реальні GET, POST та PUT: створення, назва, статус,
  фільтри, лічильники, збереження введеного тексту при помилці.
- DELETE перевірено через API-модуль застосунку; наступний GET підтвердив видалення.
  Тимчасовий запис очищено, дані перевірки не залишено.
- Перевірено контракт API з підставленими відповідями: методи, кодування id,
  використання baseURL, помилки формату даних та відсутньої конфігурації.
- Перевірено мобільну ширину 390 px без горизонтального переповнення.
- Під час початкової перевірки тестовий фреймворк не встановлювався; тепер перевірки збережено в автоматичних тестах.
